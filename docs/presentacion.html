01 · Dominio del negocio

El problema: una operatoria artesanal

Técnica Patito es una empresa de servicios técnicos domiciliarios de Córdoba que gestiona todo con mensajería, llamadas y planillas.

  • Asignaciones ineficientes: se envían técnicos sin la certificación necesaria → visitas fallidas.
  • Pérdida de oportunidades: si el técnico tarda en contestar, el pedido queda sin respuesta.
  • Falta de control: no hay certeza de que el cliente aprobó el presupuesto.
  • Conflictos de concurrencia: un pedido asignado a dos técnicos, o un técnico con más trabajo del que puede cumplir.

✅ Lo que resuelve el sistema

  • Busca solo al técnico disponible, certificado y a menos de 13 km.
  • Le oferta el trabajo con una ventana de 15 minutos; si no contesta, pasa al siguiente.
  • Exige la aprobación del presupuesto antes de empezar.
  • Limita la carga de cada técnico y evita la doble asignación.
  • Calcula el costo de la visita y deja todo en un historial auditable.

05 · Patrón Strategy (GoF, comportamiento)

Strategy: cuatro formas de cobrar la visita

Problema: el costo cambia según la prioridad y el horario. Con if/else el método crece con cada tarifa nueva.

Solución: una interfaz EstrategiaCosto y una clase por tarifa. CalculadoraCosto recibe todas por inyección y usa la que aplica().

EstrategiaCuándoRecargo
ESTANDARNormal, horario hábil0 %
PRIORIDADUrgente, horario hábil+30 %
FUERA_HORARIONormal, fin de semana / feriado / fuera de 8–18+50 %
COMBINADAUrgente y fuera de horario+80 %

Base = $5000 + km × $800 · ej.: Juan a 0,58 km → $5464,00 (ESTANDAR)

La interfaz y una de las cuatro estrategias

ms-solicitudes/src/main/java/utnfc/isi/back/tpi/solicitudes/services/costos/EstrategiaCosto.java
public interface EstrategiaCosto {

    String nombre();

    /** Indica si esta estrategia corresponde para el contexto dado. */
    boolean aplica(ContextoCosto contexto);

    BigDecimal porcentajeRecargo(Tarifas tarifas);

    default DetalleCosto calcular(ContextoCosto contexto, Tarifas tarifas) {
        BigDecimal base = tarifas.montoFijo()
                .add(tarifas.porKm().multiply(BigDecimal.valueOf(contexto.distanciaKm())))
                .setScale(2, RoundingMode.HALF_UP);
        BigDecimal recargo = base.multiply(porcentajeRecargo(tarifas)).setScale(2, RoundingMode.HALF_UP);
        return new DetalleCosto(nombre(), base, recargo, base.add(recargo));
    }
}
ms-solicitudes/…/solicitudes/services/costos/EstrategiaPrioridad.java
@Component
public class EstrategiaPrioridad implements EstrategiaCosto {
    // ... nombre() devuelve "PRIORIDAD"
    @Override
    public boolean aplica(ContextoCosto contexto) {
        return contexto.urgente() && !contexto.fueraDeHorario();
    }
    // ... porcentajeRecargo() devuelve tarifas.recargoPrioridad() (+30 %)
}

  • EstrategiaCosto L22–28: el método default fija el cálculo común (base + recargo con BigDecimal): Template Method.
  • EstrategiaPrioridad L17–18: aplica solo si es urgente y en horario hábil.

public CalculadoraCosto(List<EstrategiaCosto> estrategias, Tarifas tarifas) {
    this.estrategias = estrategias;
    this.tarifas = tarifas;
}

public DetalleCosto calcular(double distanciaKm, Prioridad prioridad, LocalDateTime fechaHora, boolean esFeriado) {
    ContextoCosto contexto = new ContextoCosto(distanciaKm, prioridad == Prioridad.URGENTE,
            esFueraDeHorario(fechaHora, esFeriado));
    EstrategiaCosto estrategia = estrategias.stream()
            .filter(e -> e.aplica(contexto))
            .findFirst()
            .orElseThrow(() -> new IllegalStateException("No hay estrategia de costo para " + contexto));
    return estrategia.calcular(contexto, tarifas);
}
  • L21: pide una List<EstrategiaCosto>: Spring inyecta las 4 implementaciones (@Component).
  • L27–28: arma el contexto: km, ¿es urgente?, ¿es fuera de horario?
  • L29–31: elige la única que aplica(); las 4 condiciones son excluyentes.
  • L33: delega el cálculo en la estrategia elegida.

Para agregar una tarifa nueva no se modifica esta clase: se crea otra estrategia (principio abierto/cerrado).

06 · Patrón Snapshot (microservicios / datos)

Snapshot: una "foto" de los datos del momento

Problema: el cliente y el técnico viven en otras bases (otros microservicios). No hay claves foráneas ni JOIN posibles, y sus datos pueden cambiar después.

Solución: al crear la solicitud se copian nombre, domicilio y coordenadas del cliente; al ofertar, el nombre del técnico.

  • Si Carlos se muda, la solicitud de hoy conserva el domicilio al que había que ir.
  • Listar solicitudes y el informe no llaman a otros servicios.
  • Si ms-clientes está caído al crear → 503 y no se guarda nada.

Se demuestra en Postman: carpeta 03 · Snapshot (el cliente se muda y la solicitud no cambia).

07 · Patrón Adapter (GoF, estructural)

Adapter: la API de mapas habla nuestro idioma

Problema: OSRM pide las coordenadas como lon,lat;lon,lat en una URL y responde metros y segundos dentro de un JSON propio. El negocio solo quiere km, minutos y de dónde salió el dato.

Solución: el negocio depende de la interfaz GeoService. OsrmGeoService adapta OSRM a esa interfaz y, si OSRM falla, usa Haversine (RN-8).

    @Override
    public Ruta calcularRuta(double latOrigen, double lonOrigen, double latDestino, double lonDestino) {
        // ... si OSRM está deshabilitado → Haversine
        // OSRM espera las coordenadas como longitud,latitud
        String coordenadas = String.format(Locale.US, "%f,%f;%f,%f", lonOrigen, latOrigen, lonDestino, latDestino);
        try {
            OsrmRespuesta respuesta = restClient.get()
                    .uri("/route/v1/driving/{coordenadas}?overview=false", coordenadas)
                    .retrieve()
                    .body(OsrmRespuesta.class);
            // ... si la respuesta viene vacía o sin rutas → Haversine
            OsrmRuta ruta = respuesta.routes().getFirst();
            double km = Haversine.redondear(ruta.distance() / 1000.0);
            int minutos = (int) Math.ceil(ruta.duration() / 60.0);
            log.info("Ruta OSRM calculada: {} km, {} min", km, minutos);
            return new Ruta(km, minutos, Ruta.Fuente.OSRM);
        } catch (RestClientException e) {
            log.warn("OSRM no disponible ({}), se usa Haversine como respaldo", e.getMessage());
            return Haversine.ruta(latOrigen, lonOrigen, latDestino, lonDestino);
        }
    }

El mapa de transiciones y quién mueve los estados

ms-solicitudes/src/main/java/utnfc/isi/back/tpi/solicitudes/models/EstadoSolicitud.java
public enum EstadoSolicitud {
    PENDIENTE, OFERTADA, ASIGNADA, EN_CURSO, REPROGRAMADA, DERIVADA, CANCELADA, FINALIZADA;

    /** Estados que ocupan un lugar "en espera" en la agenda del técnico (RN-5). */
    public static final Set<EstadoSolicitud> EN_ESPERA = EnumSet.of(OFERTADA, ASIGNADA, REPROGRAMADA);

    private static final Map<EstadoSolicitud, Set<EstadoSolicitud>> TRANSICIONES = new EnumMap<>(EstadoSolicitud.class);

    static {
        TRANSICIONES.put(PENDIENTE, EnumSet.of(OFERTADA, CANCELADA));
        TRANSICIONES.put(OFERTADA, EnumSet.of(ASIGNADA, PENDIENTE, CANCELADA));
        TRANSICIONES.put(ASIGNADA, EnumSet.of(EN_CURSO, CANCELADA));
        TRANSICIONES.put(EN_CURSO, EnumSet.of(FINALIZADA, REPROGRAMADA, DERIVADA));
        TRANSICIONES.put(REPROGRAMADA, EnumSet.of(EN_CURSO));
        TRANSICIONES.put(DERIVADA, EnumSet.of(PENDIENTE));
        TRANSICIONES.put(CANCELADA, EnumSet.noneOf(EstadoSolicitud.class));
        TRANSICIONES.put(FINALIZADA, EnumSet.noneOf(EstadoSolicitud.class));
    }

    public boolean puedePasarA(EstadoSolicitud destino) {
        return TRANSICIONES.get(this).contains(destino);
    }
}
